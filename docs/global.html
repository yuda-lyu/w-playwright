INSTALL_BUDGET_MS

Description:

  • 單次安裝(autoInstall之整體, 或ensureChromium一次呼叫)之預算毫秒: 15分鐘

    範圍: 同一次呼叫內之各安裝子行程(受管瀏覽器、Linux之系統相依)共用此上限, 逾時即結束該子行程樹並reject E_INSTALL('browser installation timed out'); 預設用於autoInstall(opt.installTimeout可改, 0表不限)與ensureChromium(opt.timeout可改, 0表不限)

    取值推導(下載時間不實測、不下載, 依本機已安裝目錄之大小與Playwright安裝行為估算):

    • 體積(本機實測目錄大小, 2026-11-26, Windows): Playwright 1.65.1(revision 1255)之headless shell安裝後約288MiB(約302MB)、完整Chromium約452MiB(約474MB); 下載之zip不大於安裝後之大小, 故以此為上界; 以0.6MB/s(約5Mbps, 偏慢之辦公室或VPN線路)下載最大者約790秒(13.2分鐘), 其餘約1.8分鐘供解壓、校驗與Linux系統相依 → 15分鐘
    • 並行: 多個行程同時首次安裝時, 本套件無自己之跨行程鎖, 只有Playwright之安裝目錄鎖(registryDirectory/__dirlock); (讀碼)lock之retries 20次、factor 1.27579、首次等1秒, 退避總和約469.5秒＝7.8分鐘(實測: 持有中之鎖使後到者於470.0秒後以離開碼1結束), 鎖之stale預設10秒(讀碼; 實測只驗已過期1小時之鎖被立即接手); 該鎖之等候發生於安裝子行程之內, 而本預算之計時涵蓋整個子行程, 故後到者「等先到者安裝之時間」已計入同一個15分鐘, 最壞仍為1倍(不乘2); 注意: 並行時後到者之有效上限為「Playwright鎖之等候上限(約7.8分鐘)與本預算之較小者」, 先到者於7.8分鐘後仍在下載(慢線)時後到者以E_INSTALL失敗(不自動重試, 使用端可重跑)

getChromiumLaunchOptions(optopt) → {Object}

Description:

  • 取得合併後之Chromium啟動選項(新物件; 供檢視與診斷); 永不拋錯

    • hook(target, info): 可為async; target為最終回傳給呼叫端之物件(launchChromium為Browser、launchChromiumPersistent為持久之BrowserContext); info為凍結物件{ fn, kind }(fn為入口函數名; kind為'browser'或'persistent'); 回傳值忽略(鉤子就地對target動作, 如掛路由、包裝close; 不能以回傳值取代target)
    • 疊放: 多個鉤子依註冊順序串行await(先註冊者先執行, 前一個完成後才執行下一個); 還原函數只移除自己這一份(不論還原順序), 重複呼叫無作用; 同一函數註冊兩次即呼叫兩次, 各自之還原函數各移除各自那一份
    • 與setBrowserTypeForTest正交: setBrowserTypeForTest為「替換」(只有堆疊頂之替身生效), 本函數為「疊放」(全部鉤子皆生效); 鉤子套在最終回傳者上, 不論來自真BrowserType或替身(含替身內next()之結果), 使用端自設替身時鉤子仍生效
    • 只對最終成功者套用一次: autoInstall之「安裝後再啟動」時失敗之嘗試不產生瀏覽器、不呼叫鉤子; 替身內next(o)之內層啟動亦不另外套用(由外層對最終回傳者套一次)
    • 失敗: 鉤子拋錯或reject時, 先關閉該瀏覽器(關閉之錯誤吞掉), 後續鉤子不執行, 再以固定詞彙之錯誤reject(code為E_LAUNCH_HOOK, 訊息'browser launch hook failed', 不附原錯誤); 原錯誤與鉤子序號只交opt.funLog('hook-error', { fn, index, code }, 原錯誤); 已執行之鉤子不回滾(鉤子自負冪等)
    • 觀察: opt.onTrace增'browser-hook'(每個鉤子完成後, { fn, index })、'browser-hook-failed'({ fn, index, code })
    • 快照: 每次啟動以「呼叫launchChromium／launchChromiumPersistent當下」已註冊者為準(與opt之快照同時); 啟動進行中(含onTrace等回調內)才註冊或還原者不影響該次啟動
    • 限制: 鉤子須會完成, 本套件不為鉤子設時限, 失敗時關閉瀏覽器亦無時限(close卡住則啟動不會reject); 鉤子內不要再呼叫會觸發同一鉤子之啟動(launchChromium、launchChromiumPersistent): 清單為全域, 會遞迴; 需要輔助瀏覽器者於鉤子內以info或旗標略過

setBrowserTypeForTest(fake) → {function}

Description:

  • 測試接縫: 以替身取代本套件所呼叫之BrowserType, 回傳還原函數; 不對外提供原始BrowserType

    替身收到的是合併後之選項(與真啟動相同, 含守門)與next:

    • fake.launch(mergedOpt, next): next()以同一份合併後選項呼叫真chromium.launch; next(o)對o重走完整流程(環境、版本、登入守門、合併)後呼叫真chromium.launch
    • fake.launchPersistentContext(userDataDir, mergedOpt, next): 同上, 對應真chromium.launchPersistentContext(未提供此方法時, launchChromiumPersistent以E_LAUNCH失敗) 替身之拋錯依真啟動之規則轉為固定詞彙錯誤(訊息含"Executable doesn't exist at"者視為受管瀏覽器缺檔)

    同一行程內使用端之src與測試取同一個主檔模組, 替換對兩者同時有效(依賴樹有兩份本套件時只作用於呼叫者那一份, 使用端之接線測試須斷言替身確被呼叫); 多次設定時以最後設定且未還原者生效(替換, 非疊放: 只有堆疊頂之替身被呼叫, 其下者不被呼叫; 需要「各處皆生效、可疊放」之啟動後處理者改用onBrowserCreated, 它與本函數正交, 自設替身時仍生效); 還原函數只移除自己這一份(不論還原順序), 重複呼叫無作用; 替身之方法以原fake物件為this呼叫
